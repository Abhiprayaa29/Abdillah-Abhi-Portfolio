- **Anonymous visitor tracking** (first-party, no third-party analytics): `script.js` mints a UUID v4, stores it in `localStorage.abhi_vid` **and** in a first-party `abhi_vid` cookie, and POSTs it to `/api/visit` after `load`. Pages Functions in `functions/api/visit.js` and `functions/api/stats.js` persist it to Cloudflare D1 (`schema.sql`, single `visitors` table: `visitor_id`, `first_seen`, `last_seen`, `visit_count`). Counting rules: a new id inserts a row and returns `isNew:true` (+1 unique); the same id inside a **60-second dedupe window** returns `duplicate:true` and changes nothing, so a refresh, a double-fired request, or a retry can never inflate the counters; the same id after the window returns `isNew:false, duplicate:false` and increments `visit_count` only, so unique stays put while `totalVisits`/`returningVisits` rise. The id is validated against `^[0-9a-f]{8}-…-…-…-…{12}$` before it touches SQL (a `1; DROP TABLE visitors;` shaped id is rejected with 400), requests are parameterised, and the response carries no IP address, user agent, referrer or identity field. Until a D1 binding exists both endpoints answer `HTTP 200 {"ok":false,"available":false}` - the route is healthy, only the counter is off - so the browser logs no failed request and the site behaves exactly as before. (A 5xx was deliberately avoided: Lighthouse's `errors-in-console` audit drops best-practices to 96 when `Failed to load resource: 503` appears in the console.)
